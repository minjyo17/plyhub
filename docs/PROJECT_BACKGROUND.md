# PlayHub 프로젝트 배경

배경 기준: 2026-11-12 대화. 구현 상태 갱신: 2026-11-13.

이 문서는 이전 대화와 스프린트 HTML의 내용을 최신 사용자 결정에 맞춰 정리한 것이다. 과거의 확대 계획과 현재 확정 범위, 앞으로 결정할 제안을 구분한다. 실제 작업 순서는 [작업 계획](WORK_PLAN.md)을 따른다.

## 1. 만들려는 서비스

PlayHub는 사용자가 링크로 접속해 설치 없이 HTML5 웹게임을 플레이하는 플랫폼이다. 게임 목록과 플레이 화면을 제공하고, 공통 SDK로 인증·점수 제출·리더보드를 연결한다.

핵심 가설은 “게임 개발자가 게임 로직에 집중하고, 반복되는 플랫폼 기능을 공통 인터페이스로 연결할 수 있다”는 것이다. 첫 결과물에서는 게임 하나로 이 흐름이 실제로 동작하는지 확인한다.

## 2. 아이디어의 출발점

제공된 이전 대화에 따르면 CCL 8기 프로젝트로 논의됐으며, 초기에는 인증·소셜·리더보드·멀티플레이·결제까지 제공하는 웹게임 포털을 구상했다.

- 공식 게임을 먼저 확보하고, 장기적으로 외부 개발자의 게임도 받을 수 있는 구조를 생각했다.
- 공통 백엔드는 Nakama를 활용하고, 게임은 플랫폼 SDK로 연결하는 방향이었다.
- 국내 관계망을 통한 공유와 간편한 진입은 장기 제품 방향으로 논의됐다.
- 결제·국내 소셜 로그인·외부 입점은 현재 구현됐거나 검증된 기능이 아니다.

이 배경은 사용자가 제공한 대화 기록에 기반한다. Slack 원문이나 CCL 제출 요건을 별도로 검증한 기록은 아니다.

## 3. 계획을 축소한 이유

연말까지 결과물을 만들어야 하고, 작업자는 1~2년차 프론트엔드 개발자 기반의 3명이다. 초기 기능을 모두 구현하기보다 일주일 안에 작동하는 최소 결과물을 만들고, 이후 스프린트에서 기능을 추가하는 방식으로 전환했다.

현재의 최소 흐름:

> 포털 접속 → 게스트 로그인 → 게임 1개 플레이 → 점수 제출 → 실제 랭킹 표시

게임 3개와 공통 로그인·랭킹은 이후 내부 최소 목표로 논의됐다. 이 기준이 CCL의 공식 완수 조건을 충족하는지는 별도로 확인해야 한다.

## 4. 최신 작업 방식

**담당자를 포털·SDK·게임으로 나누지 않는다. 각자 동일한 스프린트 목표를 전체 흐름으로 개발한다.**

- 이전 HTML의 A/B/C 역할 배정은 현재 적용하지 않는다.
- 각 작업자는 포털, 백엔드 설정, SDK 연결, 게임까지 자신의 결과물을 완성한다.
- 다른 작업자의 SDK나 서버 구현을 기다리는 구조를 전제로 하지 않는다.
- 결과물 비교·재사용·최종 통합 방식은 아직 정하지 않았다.
- 이 저장소는 현재 사용자가 개발할 하나의 결과물이다.

## 5. 현재 합의된 기술과 범위

| 항목 | 방향 | 현재 상태 |
|---|---|---|
| 프론트엔드 | Nuxt 4 + Vue 3 + TypeScript | S1 구현·검증 완료 |
| 패키지 관리 | npm, lockfile 관리 | 완료 |
| 백엔드 | Nakama + PostgreSQL을 로컬 Docker로 실행 | 2단계 완료, 재생성 후 데이터 보존 확인 |
| 게스트 인증 | Nakama 인증을 포털 내부 SDK로 감싸서 사용 | 구현 완료 |
| 점수·랭킹 | 게임별 리더보드 | 테스트·게임별 실제 저장·랭킹 화면 연결 완료 |
| 첫 게임 | 가벼운 싱글플레이 게임 1개 | 독립 Snake Garden 구현·SDK 연결 완료 |
| 포털 | 게임 목록·상세·플레이 화면 | 구현 완료 |
| Git | 로컬 저장소 및 프로젝트 전용 작성자 설정 | 완료 |
| 원격 저장소 | 사내 GitLab 대신 GitHub 사용 예정 | 원격 연결 전, 인증은 사용자가 직접 설정 |

React 프로젝트로 시작했지만 사용자의 요청으로 Nuxt로 전환했다. 기존 React/Vite 단독 앱 구조를 개발 기준으로 사용하지 않는다. Nuxt 내부 빌드 도구로 사용되는 Vite는 별개다.

백엔드 기능은 Nakama의 제공 기능을 우선 사용한다. 리더보드 초기화처럼 필요한 최소 런타임 설정은 허용하되, 별도 인증 서버나 게임 서버를 직접 만드는 범위로 확대하지 않는다.

## 6. 이번 스프린트에서 제외한 기능

- 이메일·Google·Kakao·Naver 등 추가 로그인
- 친구·프로필 등 소셜 기능
- 멀티플레이·매치메이킹·파티·토너먼트
- 실결제 및 결제 목업
- 외부 개발자 입점·게임 업로드·정산
- 공개 서비스 수준의 점수 조작 방지
- 여러 게임과 정교한 포털 디자인

초기 대화에서는 소셜 등 일부 항목이 필수였지만, 최종 축소 계획에서는 S1 범위에서 제외됐다. 이후에도 구현 여부를 스프린트마다 다시 판단한다. 결제를 다루게 되더라도 현재 합의는 목업·데모 수준까지다.

## 7. 현재 저장소에서 완료된 일

- Nuxt 4.6.4, Vue 3, TypeScript 기본 프로젝트
- 기본 안내 화면 `app/app.vue`
- 실행·타입 검사·빌드 명령과 의존성 lockfile
- Node 22.22.3 지정 및 로컬 설치
- 타입 검사, 프로덕션 빌드, 빌드 서버 HTTP 200 응답 확인
- 로컬 Git 저장소 초기화 및 프로젝트 전용 개인 작성자 설정

이후 사용자 요청으로 1단계 최소 테스트 화면과 2단계 로컬 백엔드를 완료했다. Nakama·PostgreSQL은 실제 실행되며, `playhub-test` 리더보드에 기록한 점수가 컨테이너 재생성 후에도 남는 것을 확인했다.

**독립 게임 SDK·포털 브리지·서버 랭킹 연결을 완료했다.** 브라우저의 게스트 UUID로 같은 계정을 이어 사용하고, 점수와 순위는 Nakama에서 저장·조회한다. 외부 SDK는 packages/game-sdk에 있고 /play/snake에서 독립 게임을 실행한다. 새 Linux 설치 재현과 최종 통합 검증을 마쳤으며 데모 가이드와 s1-demo 태그로 시연 버전을 보존한다. 게임 소스는 포털과 독립적으로 두고 실행 URL과 공개 SDK로 연결한다. 샘플 게임은 이 연동을 검증하는 용도다. 전체 실행 방법은 [게임 SDK 가이드](GAME_SDK.md)를 참고한다.

## 8. 남아 있는 결정과 제약

- CCL의 공식 완수 기준과 제출 산출물 확인
- 실제 작업 가능 시간, 첫 데모 날짜 확정
- 첫 게임 종류 선택
- 각자의 결과물 평가 및 통합 방식 결정
- GitHub 인증과 원격 저장소 준비: 사용자가 직접 설정
- 공개 배포 환경과 도메인: 이후 결정

로컬의 기존 npm 전역 prefix 설정과 nvm 사이에 충돌이 있어 현재는 프로젝트용 Node 경로를 지정해 실행할 수 있다. 방법은 [README](../README.md)에 기록돼 있다.

2026-11-12 설치 시점의 의존성 검사에서는 낮음 6건·보통 6건의 경고가 남았다. 호환 범위 자동 수정으로 해소되지 않았으며, Nuxt 다운그레이드를 포함하는 강제 수정은 하지 않았다. 공개 배포 전에 다시 점검한다.
