# S1 데모 실행 가이드

S1 목표: 포털에서 독립 게임을 게스트로 플레이하고 종료 점수가 실제 랭킹에 나타난다.
시연 버전은 로컬 Git 태그 `s1-demo`로 보존한다. GitHub 업로드는 별도다.

## 준비

- Node.js 22.22.3, npm, Docker Desktop/Compose
- 저장소 전체 필요: 게임의 SDK 의존성은 `file:../../../packages/game-sdk`
- 포털 3317, 게임 3318, Nakama 7350·7351 포트 사용
- 이미 해당 서버가 실행 중이면 중복 기동하지 않고 아래 접속 확인부터 진행
- `node --version`으로 버전 확인. nvm과 사용자 npm prefix가 충돌하는 이 PC에서는 현재 셸에만 `export PATH="/Users/jhomin/.nvm/versions/node/v22.22.3/bin:$PATH"` 적용 가능

## 처음 실행하기

터미널 1, 저장소 루트에서:

```sh
npm ci
npm run backend:up
npm run backend:check
npm run typecheck
npm test
npm run build
NITRO_HOST=127.0.0.1 NITRO_PORT=3317 node .output/server/index.mjs
```

터미널 2, 저장소 루트에서:

```sh
cd examples/games/sdk-demo
npm ci
npm test
npm run build
npm run preview
```

- 홈: http://127.0.0.1:3317/
- 게임 상세: http://127.0.0.1:3317/games/snake
- 개발자 가이드: http://127.0.0.1:3317/guide
- 구조 설명: http://127.0.0.1:3317/sdk
- Nakama 콘솔: http://127.0.0.1:7351 (로컬 기본 계정은 LOCAL_BACKEND.md 참고)

개발 중에는 포털의 마지막 두 명령 대신 `npm run dev -- --host 127.0.0.1 --port 3317`, 게임은 `npm run dev`를 사용한다.

## 3~5분 시연 순서

1. **홈**: 로그인 버튼과 실제 게임 목록을 보여준다. 현재 등록 게임은 Snake Garden 한 개다.
2. **상세**: 게임 카드를 눌러 소개·조작법·플레이 버튼·랭킹 영역을 확인한다. 비로그인 상태라면 랭킹 로그인 안내가 표시된다.
3. **로그인**: 플레이하기 → 게스트로 로그인. 별도 가입 없이 게임으로 이동하며, 이미 로그인했다면 바로 실행된다.
4. **플레이·저장**: 시작하기를 누른다. 조작하지 않으면 먹이를 먹고 벽에 닿아 종료된다. 게임과 포털의 저장 완료 안내, 실제 랭킹을 보여준다.
5. **다시하기**: 다시하기로 새 판을 시작한다. 두 번째 판 종료 후에도 최고 기록이 유지된다.
6. **복귀·재진입**: 게임 상세 → 모든 게임 → 카드 → 플레이하기. 같은 사용자와 기록을 유지한 채 새 게임판이 열린다.
7. **새로고침**: 상세에서 브라우저 새로고침. 같은 게스트와 내 최고 기록이 복원된다.
8. **구조 설명**: `/sdk`에서 독립 게임 → 공개 SDK → 포털 브리지 → Nakama → PostgreSQL 흐름을 설명한다. `/guide`에서 개발자가 사용하는 세 함수를 보여준다.

## 선택 시연: 실패 복구와 기록 보존

- 진행 중인 판을 종료하기 직전에 개발자 도구로 네트워크를 끊으면 저장 실패 안내가 나온다. 연결을 복구하고 게임의 점수 저장 다시 시도를 누른다. 미저장 최고 점수는 페이지를 닫기 전까지 메모리에 유지된다.
- 서버 영속성 확인은 `npm run backend:check` → `npm run backend:down` → `npm run backend:up` → `npm run backend:verify` 순서다. 마지막 명령은 기존 infra_check 계정의 12,345점을 쓰기 없이 조회한다. 실제 게임 기록은 상세 랭킹에서도 확인한다.
- 서버 종료에는 `docker compose down`을 사용한다. `down -v`는 데이터 볼륨을 지우므로 일반 시연 종료에 사용하지 않는다.
- 포털·게임 프로세스는 각각 실행한 터미널에서 Ctrl+C로 종료한다.

## 알려진 제약

- 게스트 인증만 제공한다. 이메일·소셜 로그인과 계정 복구는 S1 범위 밖이다.
- UUID는 브라우저 사이트 저장소에 있다. 사이트 데이터 삭제, 다른 origin/프로필에서는 기존 계정으로 돌아가지 못할 수 있다.
- 로그아웃은 현재 탭의 자동 복원을 멈추며 저장된 UUID·서버 기록은 지우지 않는다. 다시 로그인하면 같은 게스트로 돌아온다.
- 클라이언트 계산 점수를 받는 데모다. 출처 검증이 점수 조작 방지를 보장하지 않는다.
- SDK는 로컬 패키지이며 npm에 게시하지 않았다. 게임 등록은 코드·설정으로 관리한다.
- 게임 주소 3318을 직접 열면 연습 모드다. 서버 기록은 PlayHub 안에서 실행할 때만 제출한다.
- 저장 실패 점수는 메모리에 보관한다. 새로고침·게임 새로 열기·페이지 닫기 전에 재시도해야 한다.
- 상위 랭킹은 로그인 후 조회한다. 같은 최고 점수끼리의 세부 순서는 서버 순위를 따른다.
- 현재 주소와 기본 자격 정보는 로컬 개발용이다. 외부 배포·운영 인증·HTTPS 구성은 이번 시연 범위에 포함하지 않는다.
